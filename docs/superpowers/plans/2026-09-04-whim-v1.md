# Whim v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Whim v1 as an offline-first iPhone and Apple Watch voice-note app that records immediately, titles Notes on-device, and delivers them to one signed, idempotent webhook.

**Architecture:** An Expo Router/React Native iPhone presentation layer talks through the `expo-whim` workspace package to the shared Swift package `WhimCore`. `WhimCore` owns canonical state, recording, persistence, delivery, recovery, retention, and cross-device merge rules; SwiftUI Watch, App Intent, Live Activity, and WidgetKit targets invoke the same package without JavaScript. Repository structure follows screaming architecture: target roots establish build ownership, then capability folders such as Recording, Delivery, Recovery, and Device Sync own their implementation, interfaces, adapters, and adjacent tests. Work is delivered in vertical test-driven slices, with unit, integration, iPhone E2E, and Watch E2E suites runnable from stable root commands from the first task onward.

**Tech Stack:** Expo SDK 57, React Native, TypeScript, npm workspaces, Expo Router, Expo Modules API, Swift 6, SwiftUI, GRDB/SQLite, AVFoundation, Speech, WatchConnectivity, App Intents, ActivityKit, WidgetKit, Jest, React Native Testing Library, Expo Router testing library, XCTest/XCUIAutomation, Maestro, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-04-whim-v1-design.md`

## Global Constraints

- Minimum iPhone version is iOS 18; minimum Watch version is watchOS 11.
- Commit the generated `ios/` project; stock Expo Go is unsupported.
- React Native owns iPhone presentation only; canonical Note, Delivery, recording, and configuration state belongs to `WhimCore`.
- The Watch records and stores Notes independently and may race iPhone delivery with the same Note ID.
- The iPhone app and its extensions use App Group `group.app.whim.shared`; the Watch app and Watch complication use `group.app.whim.watch.shared`. The two groups never substitute for Watch Connectivity.
- Audio is AAC-LC mono in an `.m4a` container; `RecordingLimits.maximumDuration` is 300 seconds.
- V1 persists stable Workflow ID `default` and Step IDs `title_enrichment` and `webhook_delivery`; it does not implement a generic workflow executor or plugin system.
- Webhook configuration is one HTTPS URL plus optional bearer token, optional HMAC secret, and at most ten custom headers.
- A Receipt is absorbing; no later failure or stale cross-device message may regress a sent Note.
- Offline state consumes no Attempt. Retryable failures run immediately, then after one minute and fifteen minutes, with at most three actual failed Attempts.
- Delivery waits at most 300 milliseconds for a title. Transcription is on-device-only and full transcript text is never persisted.
- Default retention is 30 days after successful delivery. Unsent, failed, setup-required, and recovered Note audio never expires automatically.
- There is no account, Whim backend, cloud sync, analytics, diagnostics, crash reporting, or telemetry.
- Every behavior change starts with a failing companion test at an agreed public seam. Changed end-user journeys receive companion E2E coverage.
- Unit and integration tests live beside the implementation they verify using `*.test.*` and `*.integration.test.*`. Only E2E tests have standalone directories.
- Folder names describe Whim capabilities. Generic technical-layer or dumping-ground directories such as `Domain`, `Ports`, `Services`, `Adapters`, `features`, `components`, `common`, and `utils` are not used.
- Root commands `test:unit`, `test:integration`, `test:e2e:iphone`, `test:e2e:watch`, `test:e2e`, and `test:all` remain stable.

The repository root is the Expo project root, so Expo owns root `ios/` while Expo Router is configured explicitly for `src/iphone/app`. The root npm workspace includes `packages/expo-whim`, and the app declares `@whim/expo-whim` as a workspace dependency so Metro and Expo Autolinking traverse only an explicit module interface.

`WhimCore` is also exposed as a local CocoaPod from the same `Sources` tree so `expo-whim` can depend on it. The Watch, Intents, and Widget targets link the Swift package product directly. No implementation is duplicated between the Pod and Swift Package integration paths.

Every non-E2E test is physically adjacent to the file or capability it verifies. Expo Router files contain no behavior because Router forbids tests inside its route directory; route behavior is implemented and tested in the adjacent capability folder. SwiftPM production, unit-test, and integration-test targets use explicit, non-overlapping source lists over the same capability tree, and CocoaPods excludes `*.test.swift` and `*.integration.test.swift`. `scripts/check-test-colocation.mjs` fails when a test is not beside its named implementation or a Swift file is absent from the correct manifest source list.

Every task that adds or moves Swift files also updates the explicit `Package.swift` source lists or Xcode target membership in the same change. Production targets never compile adjacent tests; test bundles never become runtime dependencies. Capability folders may contain narrowly scoped `Fixtures` or `TestSupport` children, but repository-wide `tests`, `common`, or `utils` dumping grounds are prohibited.

- [x] **Step 3: Implement the reducer and retry policy minimally**

`DeliveryReducer` is pure. It preserves the first Receipt, accepts any later Receipt as success without regressing, and computes visible status from configuration, connectivity, lease, Attempts, and Receipt. `RetryPolicy` classifies network errors plus 408/425/429/5xx as retryable, all other 4xx as permanent, and returns these earliest offsets for failed Attempt counts:

```swift
public enum RetryPolicy {
    public static let maximumFailedAttempts = 3
    public static let delays: [TimeInterval] = [0, 60, 900]

    public static func nextEligibility(after failures: Int, now: Date, retryAfter: Date?) -> Date? {
        guard failures >= 0, failures < maximumFailedAttempts else { return nil }
        let policyDate = now.addingTimeInterval(delays[failures])
        return max(policyDate, retryAfter ?? policyDate)
    }
}
```

Watch finalization starts its own eligible Delivery and queues file plus metadata to iPhone immediately. iPhone may import and deliver using the same Note ID. Both generate distinct Attempt IDs. Import works whether file or metadata arrives first. iPhone transcribes imported audio and sends title/status back; title arrival never triggers a second webhook request. Simulator E2E injects envelopes and fixture files through a debug-only `PeerTransport`; the paired-device suite verifies the real `WCSession.transferFile` path because Watch Simulator does not support that API.

- [ ] **Step 5: Implement configuration and deletion synchronization**

Each device uses its highest known Configuration Revision. Older-endpoint success still produces a Receipt. Older-endpoint failure imported to iPhone becomes eligible under the newest configuration. Tombstones persist until both paired endpoints acknowledge, and stale Note transfers cannot resurrect deleted data. Reset uses the same acknowledgement discipline.
